# PRD — Product Requirements Document

**Filename slug:** `prd`

## Questions

**Q1 — What feature or capability is this PRD for?** Freeform.

**Q2 — What user problem does this solve?** Freeform. Pre-fill from CONTEXT.md.

**Q3 — What are the success metrics? How will you know this worked?** Freeform.

**Q4 — Are there technical constraints engineering has flagged?**
- Yes, let me describe them → freeform follow-up
- No constraints yet → include an open questions section
- Not sure → flag as something to confirm with engineering

**Q5 — Target release timeframe?** Freeform, or pre-fill from the roadmap.

## Output sections

Overview · Problem Statement · User Stories (as a user I want… so that…) · Functional Requirements (table: ID, Requirement, Priority, Acceptance Criteria) · Non-Functional Requirements (performance, security, accessibility) · Success Metrics · Timeline & Milestones · Dependencies · Open Questions · Appendix

## Pre-fill

Cross-reference DECISIONS.md for locked-in technical or product decisions — a PRD that contradicts a logged decision is worse than no PRD.
